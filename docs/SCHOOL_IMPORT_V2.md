# 학교 자료 가져오기 양식 v2

배포 버전: `v2.2.0`. 앱의 각 자료 화면에서 내려받는 `ClassHub-종류-양식.json`이 실제 입력 양식이다. 사용자는 원본 자료와 이 양식을 외부 AI에 직접 전달하고, 완성된 JSON을 확인한 다음 가져온다. 원본 HWP/XLSX를 ClassHub가 자동 해석하는 기능은 아직 없다.

## 공통 구조

| 필드 | 역할 |
| --- | --- |
| `format`, `version`, `kind` | `ClassHubSchoolData`, `2`, 자료 종류. 기존 v1 파일도 가져올 수 있다. |
| `source` | 문서 제목, 학년도, 학교, 파일 종류, 조회·촬영 시각, 쪽 또는 시트. |
| `overview` | 연간 학사일정의 월·학기·연간 수업일수와 원본 주간 표. 다른 종류에서는 필요한 요약 정보를 보존. |
| `records` | 앱에 넣을 각 행사·층·교시·성적·생기부 항목. |
| `unresolved` | 날짜·장소·점수 등 판독되지 않은 부분. 추측해서 채우지 않는다. |
| `examples`, `fieldGuide` | 작성 설명이다. 예시를 실제 기록으로 복사하지 않는다. |

값이 원본에 **0**으로 적힌 경우에는 `0`, 빈 칸이거나 읽을 수 없는 경우에는 `null` 또는 빈 문자열을 쓴다. 개인 기록의 긴 문장은 요약문 대신 원문 전체를 보존한다. 각 항목에 원본 쪽수·시트·셀·행을 기록해 가져오기 전에 대조할 수 있도록 한다. 원본에만 있는 열은 같은 이름으로 record에 추가하면 `sourceDetails`에 보존된다.

## 첨부 자료와 항목 대응

### 학사일정 HWP

첨부 문서는 2026학년도 3월부터 2027년 2월까지 이어지는 주간 표다. 행사와 함께 월별 학년별 수업일수, 1·2학기 각 95일, 학년별 연간 190일이 있다.

- `overview.academicYear`: 2026.
- `overview.monthlyInstructionDays`: 월마다 `{month, byGrade:{"1":…, "2":…, "3":…}}`.
- `overview.semesterInstructionDays`, `annualInstructionDays`: 원본 합계.
- `overview.weeklyRows`: 월/주, 일~토 날짜 칸, 주요 행사 원문, 출처 쪽. 원본 표 자체를 되짚을 수 있게 보관.
- `records`: 주요 행사 하나당 하나. 하루 행사와 여러 날 행사, 학년 대상, 휴업으로 수업이 없는지, 원문을 분리해 기록. 월을 넘는 상담주간도 실제 시작·끝 날짜로 쓴다.
- `unresolved`: 예를 들어 날짜가 ‘미정’인 준비기간. 달력 일정으로 임의 생성하지 않는다.

현재 달력은 확정된 행사를 표시한다. 월별 수업일수와 원본 주간 표는 ‘가져온 원본 요약’에서 확인할 수 있다. 수업일수를 달력에 자동 계산·검증해 표시하는 화면은 별도 작업이다.

### 학교 배치도 XLSX

첨부 파일은 `전체` 시트에 1~5층을 세로로 이어 배치한 도면이다. 교실뿐 아니라 교무실, 학습실, 도서관, 계단, 화장실, 중앙현관, 식당, 실외 공간 등이 있다. 셀 병합과 간격에도 위치 정보가 담겨 있다.

현재 학교 지도 화면의 기본 사용법은 **층별 사진을 직접 올리는 방식**이다. 외부 AI에는 원본 지도 사진을 보내 층별 영역 자르기, 기울기·회전·대비 보정, 읽을 수 있는 시설 목록 확인을 요청한다. JSON이나 좌표 양식은 만들 필요가 없다. AI가 만든 층별 PNG/JPG 파일을 학교 지도 탭에서 한꺼번에 올리고, 마커는 사진 위에서 직접 놓는다. 마커 이름·설명·색·모양·위치는 앱에서 바꿀 수 있다. 원본에 없는 시설을 AI가 만들어서는 안 된다.

아래 `map` JSON 설명은 이전 방식으로 가져온 기록을 해석하기 위한 호환 정보다. 새 지도를 만들 때는 사용할 필요가 없다.

- 층마다 map record 하나. `floor`, `sourceSheet`, `sourceRows`를 기록하고 건물명이 원본에 있을 때만 `building`을 채운다. 건물명이 비어 있어도 층별 지도는 가져올 수 있다.
- 외부 AI에는 층별 도면 이미지를 잘라 내고 회전·기울기·대비를 정리해 별도 이미지로 출력하도록 요청한다. JSON의 `floorImageFile`에는 해당 파일 이름을 적는다. 이미지는 앱의 해당 층에서 직접 첨부하며 이 기기에 저장된다.
- `gridLayout`과 `gridCells`는 원본 표 구조를 별도로 보존하고 싶을 때만 기록한다.
- `rooms`: 장소 이름, 종류, 교실 번호, 원본 셀, 확인한 윤곽 좌표. `features`: 위치가 확인된 계단·출입구·안전시설 등의 표식. `paths`: 확인한 복도·동선.
- 정확한 지도 윤곽을 읽을 수 없으면 `polygon: []`로 둔다. 이 장소는 지도 아래 ‘위치를 확정하지 못한 장소’에 표시하고 원본 셀 정보도 남긴다. 보이지 않는 소화기나 비상구를 추정해 추가하지 않는다.

셀 도면만으로 정확한 건축 평면도나 실제 거리·출입문 방향을 확정할 수는 없다. 시각화 좌표는 원본 배치를 참고한 **표시용 좌표**다.

건물명이 없는 층별 JSON도 가져올 수 있다. 방과 시설 목록은 비어 있어도 된다. 층 이미지를 첨부하지 않았고 `gridLayout`·`gridCells`가 있으면 원본 표의 셀 배치를 대신 그린다. 셀 배치는 실제 건축 도면이 아니다.

시간표 파일은 교시의 시작 시각만 확인되면 `end`를 비워 가져온다. 원본에서 수업이 없는 칸은 `subject: ""`로 기록해 빈 교시로 표시한다. 종료 시각은 사용자가 교시별 시간 설정에서 확인하거나 자동 채우기를 적용한 뒤 기간 일정에 추가한다.

### 나이스플러스 성적 화면

첨부 화면에는 고사별 과목 점수와 평가 항목, 학기 과목 합계, 원점수, 성취도, A~E 성취도별 분포, 석차·동석차, 수강자 수, 과목 평균, 성취율 구간, 체육·예술의 수행 항목과 교양과목 이수 여부가 보인다.

- `assessment`: 지필·수행 평가 항목마다 한 건. 이름, 구분, 반영비율, 만점, 받은 점수.
- `examResult`: 중간·기말 등 고사별 과목 결과.
- `courseResult`: 학기 과목별 합계, 원점수, 성취도와 분포, 석차·동석차, 수강자 수, 과목 평균, 성취율 구간.
- `completion`: 교양과목의 학점·이수 여부·P 표기.
- `mockExam`, `analysis`, `errorSheet`: 모의고사, 성적분석, 정오답표가 원본에 있으면 각각 별도 건. 첨부 화면에 없는 값은 추측하지 않는다.

### 전국연합학력평가 종합 성적통지표

제공된 종합 성적통지표 사진은 과목별 원점수·표준점수·백분위·등급 외에 학교/전국 석차와 응시자 수, 전국 누적 백분율, 등급별 비율, 표준점수 분석, 문항별 정오답을 담고 있다. 과목마다 `mockExam` 기록을 만들고 `area`, `electiveSubject`, `score`, `full`, `standardScore`, `standardScoreRange`, `percentile`, `rank`, `schoolRank`, `schoolParticipants`, `nationalRank`, `nationalParticipants`, `nationalCumulativePercent`, `mockGradeDistribution`, `standardScoreAnalysis`, `answerSheet`를 원문 값 그대로 기록한다. 영역별로 없는 열은 `null` 또는 빈 배열로 남긴다. 응시자 전체 비교표처럼 과목 한 건에 속하지 않는 표는 `overview`에 보존한다. 문항 번호·표시 답·정답·정오·배점·난도를 `answerSheet`의 별도 항목으로 기록한다. 표에 없는 석차나 백분위를 계산해 채우지 않는다.

점수가 있는 건 현재 성적 관리 목록에, 점수가 없는 분석·이수 기록은 원문 보관 목록에 들어간다. 세부 평가별 분석 화면은 아직 이 모든 유형을 별도 그래프로 해석하지 않는다.

### 나이스플러스 학교생활기록 화면

첨부 화면에는 과목별 긴 세부능력·특기사항, 학년별 출결상황, 수상경력이 보인다. 출결은 수업일수와 결석·지각·조퇴·결과의 질병/미인정/기타를 분리한다. 수상은 학년·학기·수상명·등급·수상일·수여기관·참가대상을 분리한다.

- `narrative`: 과목별 세특, 창의적 체험활동 하위 영역, 행동특성 등. `cv`에 원문 전체.
- `attendance`: 학년별 `attendance.schoolDays`, `absence`, `late`, `earlyLeave`, `classExit`, `remarks`.
- `award`: 수상명과 `award.rank/date/institution/eligibleGroup/eligibleCount`.
- 자격증, 독서, 봉사, 학교스포츠클럽 등 다른 영역도 별도 record로 만들고 원래 필드를 함께 보존.

현재 이 기록은 활동 관리 및 원문 보기에서 확인한다. 출결 전용 통계 화면과 생기부 원본과 동일한 표 화면은 아직 없다.

## 가져오기와 보존

### 추가로 확인한 나이스플러스 화면 반영

성적표에서 같은 과목의 `assessment`, `examResult`, `courseResult`에는 동일한 `courseKey`를 기록한다. `schoolYear`, 학년, 학기, 과목명과 이수 단위도 각각 유지한다. 평가 항목의 반영 비율과 만점·받은 점수는 학기 합계와 별도 행이며, 분석 평균에 중복 합산하지 않는다. 소수점 합계와 반올림된 원점수, 성취도 분포율과 성취율 구간 문구, 석차와 동석차 인원은 별도 필드다. 체육·예술의 A~C 성취도와 교양의 P 이수는 원본에 없는 등급이나 점수로 보정하지 않는다.

학교생활기록 화면의 교과학습발달상황은 과목·학점·원점수·과목평균·성취도·성취도 분포·석차등급(`rankGrade`)·석차(`classRank`)·동석차 인원(`jointRank`)·수강자수·비고를 `courseRecord`로 보존한다. 석차등급과 석차는 서로 다른 값이며, 원본에 없는 석차등급은 추정하지 않는다. 여러 과목을 묶은 세특은 `subjects` 배열과 원문 `cv`를 함께 기록한다. 봉사활동은 날짜/기간, 장소·주관기관, 활동 내용, 시간과 누계를 `volunteer`로 기록한다. `reportStatus`는 `provided`, `notProvided`, `empty`를 구분한다. 빈 칸이나 미제공 항목을 0으로 추정하지 않는다.

위 항목은 기존 v2 JSON에 추가 가능한 필드다. 가져오기 화면에서 전용 표나 통계를 모두 제공하는 것은 아니며, 원본 추가 필드는 각 기록의 `sourceDetails`에서 확인한다.

JSON을 읽을 때 날짜·점수·지도 좌표 등 기본 형식을 확인한다. 가져오기 전에 건수와 항목을 보여 주며 기존 기록은 유지한다. 날짜 미정 항목과 학사일정 요약은 별도로 보관한다. 원본 HWP/XLSX/PDF/이미지는 브라우저의 로컬 이미지 저장소에 저장할 수 있고, 구조화한 기록과 요약은 계정 동기화 대상이다. 민감한 원본을 외부 AI에 보낼지는 사용자가 직접 결정한다.

이 양식은 **첨부된 화면·문서에서 확인한 항목을 보존할 수 있도록 설계**했다. 나이스플러스의 모든 학교·연도·성적표 변형을 자동 판독한다고 검증한 것은 아니다. 새 항목이 나타나면 원문 이름 그대로 record에 추가하고, 가져온 뒤 원본과 대조한다.
